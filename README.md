# TA Flow

**在 BOSS 直聘和猎聘上，自动把人找出来。**

一套装在招聘同学自己电脑上的 RPA：主动搜索 + 翻页 + 读详情 + 逐个打分，
把「今天要找到 30 个像样的人」从体力活变成一次点击。
单人单机 · Electron + Vue 3 + SQLite · Windows

## TA Flow 是什么

**核心是一个跑在真实浏览器里的寻访 RPA。** 你给它一个 JD 和搜索条件，它驱动你自己
已登录的 Chrome，在两个平台上把候选人翻出来、读进来、打成可比较的分，落进本地人才库。

| 平台 | 怎么找人 | 边界 |
|---|---|---|
| **BOSS 直聘** | 推荐流无限下滑，逐卡片读、逐人打分，可按规则打招呼 / 收藏 | 拟人化点击，日配额 + 风险熔断 |
| **猎聘** | 主动填条件搜索 → 翻页 → 进详情精筛（两阶段） | **只读不写**，不打招呼、不收藏 |

两个平台的检测机制完全不同（BOSS 是 DOM 蜜罐 + 会话级校验，猎聘是 JS 侧全局变量探针 +
阿里云 WAF），所以探针各写各的，不会用一套逻辑硬套两个平台。

**评分为 RPA 服务。** 找人的动作解决了"翻"，评分解决了"判断"——它把每个翻到的人打成
同一个 JD 下可比较的分数，让 RPA 知道该停下来看谁、该不该打招呼。评分引擎本身不联网、
不调大模型，是纯函数，见下方[评分引擎](#评分引擎rpa-的判断依据)一节。

**默认不联网、数据不出本机、敏感字段加密落盘。**

> ### 这个仓库不含任何业务数据
>
> 它是一套通用工具，不是某个公司的内部系统。岗位库、平台账号、飞书租户、Excel 台账
> 全部由你自己在 `config/` 里配。**换一家公司、换一套岗位，只改配置，代码一行不动。**
> 三步接上：见 [接入你的业务数据](docs/接入你的业务数据.md)。

## 它解决什么问题

| 痛点 | TA Flow 的做法 |
|---|---|
| **BOSS 推荐流几百人，只能靠手滑鼠标** | RPA 自动下滑翻页，逐人读卡片 + 打分落库 |
| **猎聘要反复填搜索条件、翻 100 页** | 一次配好条件，自动搜索 → 翻页 → 进详情 |
| **翻到的人要一个个点开看** | 两阶段：列表级广撒网，详情级只精筛值得的，配额不浪费 |
| 翻页翻快了怕封号 | 拟人化节奏 + 闭环风控，命中风险自动退避熔断 |
| 打招呼点快了怕封号 | 打招呼前查覆盖度，证据不足不发 |
| 同一堆技术词分不出两拨人 | `domainFit` + `taskCoverage` 占 40% 权重，专门区分应用域 |
| 简历要上传到别人服务器才给打分 | 全程本机计算，简历不出磁盘 |

## RPA 能做什么

### 平台能力矩阵

| 能力 | BOSS 直聘 | 猎聘 |
|---|---|---|
| 主动搜索筛选 | 不需要（推荐流） | ✅ 必填条件 + 点搜索 |
| 翻页 | 无限下滑 | ✅ ant 分页器，最多 100 页 |
| 读列表卡片 | ✅ | ✅ |
| 进详情读简历 | ✅ 分段滚动模拟阅读 | ✅ 详情级精筛 |
| 打招呼 | ✅ 可配置 | ❌ **恒不实现** |
| 收藏 / 关注 | ✅ | ❌ |
| 三重配额门控 | 日配额 | 翻页 / 搜索 / 详情 三配额 |
| 风险探针 | DOM 蜜罐 + 会话校验 | JS 侧检测 + 阿里云 WAF |

### 一次运行里发生什么

1. **启动** — 打开你已登录的专用 Chrome profile（独立端口，不碰日常浏览器）
2. **前置闸** — 检测窗口是否可见、夜间时段、当日配额、账号健康基线
3. **翻页** — 拟人化滚动 / 点击，读卡片，遇风控信号立即分级处置
4. **详情** — 分段滚动读简历正文，提取评分要用的字段（长文本只在内存参与算分，不落库）
5. **打分** — 每个候选人按当前 JD 打 14 维加权分 + 覆盖度
6. **动作** — 按阈值决定打招呼 / 收藏 / 跳过（打招呼前复核覆盖度）
7. **落库** — 候选人 + 分数 + 风险事件进本地 SQLite
8. **收尾** — 配额对账、风险指数更新、可导出

单次运行最长 90 分钟，到点自动停。

### 为什么它"慢"

这是设计选择，不是没优化：

- **人等价速度** — 追求跑得像人，不追求跑得快。固定节奏本身就是最强的自动化指纹。
- **窗口必须可见** — 最小化或被完全遮挡时 Chrome 不处理 CDP 输入事件，
  `Input.dispatchMouseEvent` 永不回执。引擎会**在开跑前检测并拒绝启动**——
  "跑出一个假的任务完成"比不跑更糟。
- **夜间禁跑 22:00–07:00** — 硬约束，不可配置。
- **命中风控自动退避** — 不是降速，是暂停，按冷却等级分级恢复。

## 评分引擎：RPA 的判断依据

RPA 解决了"翻"，但它需要一个标准来决定**翻到的人里谁值得停下来看、谁可以打招呼**。
这就是评分引擎的角色——它是 RPA 的手眼，不是独立的简历筛选器。

大多数"AI 筛简历"的失败方式是一样的：把同一堆技术词打成一档，分不出
**「金融风控引擎」和「电商推荐引擎」是两拨人**。如果 RPA 用这样的分数去决定打招呼，
就会把招呼打给错的人，而且不可撤回。

TA Flow 的评分引擎用 14 个维度加权，其中 `domainFit`（应用域）和 `taskCoverage`（任务点）
合计占 40% 权重，专门解决这件事。两个设计上的硬约束：

1. **判不了的维度整维退出加权**，不占权重也不拉低比例——宁可少一个维度，不虚构一个分数。
2. **权重按「实际参与加权的维度之和」归一化**，所以模板合计是 107 而不是 100，只有比例有意义。

评分是可解释、可复现的纯函数（`src/shared/scoring-universal.js`，App 与浏览器插件共用同一份），
不调用任何大模型。想接语义匹配，引擎预留了 `setSemanticProvider()` 接口。

引擎本身与行业无关——它只认你 JD 里写的 `domain` 与 `tasks`。
你所在领域的专有词，配在岗位的 `domain.keywords` 里即可。

> **每个分数都带数据覆盖度。** 覆盖度低于 60% 不会被判为"高匹配"，也不会触发自动打招呼——
> 打招呼不可撤回，证据不足就不发。

> **语义匹配默认关闭**，这是有对照实验支撑的结论而非"没敢开"：
> 开启后分档命中率不变但 MAE 从 1.5 涨到 6.0，标定变差。详见 [引入 LLM 的可行性](docs/ai-in-scoring-feasibility.md)。

## 为什么是"本地"，不是 SaaS

招聘场景里的数据是候选人的简历、电话、在职公司。把它们传到别人的服务器上，
无论对方怎么承诺，风险都转移给了候选人。

所以这个项目的所有约束都指向同一个方向：

- **零服务器**：没有后端，没有账号体系，所有计算在本机完成
- **零候选人上传**：简历数据不离开本地磁盘
- **零密码存储**：不保存任何招聘平台的账号密码（用你自己已登录的浏览器）
- **可一键清空**：设置里有「清空所有本地数据」，会同时清掉数据库、日志与风控历史

## 快速开始

**环境要求**：Node.js >= 18、Windows 10/11、Chrome

```bash
git clone https://github.com/yystudio-cyber/ta-flow.git
cd ta-flow
npm install

# 1. 复制配置模板
cp config/jd-config.example.json  config/jd-config.json
cp config/workflow.example.json   config/workflow.json

# 2. 按自己的岗位 / 平台 / 租户改这两份 JSON
#    详见 docs/接入你的业务数据.md

# 3. 自检 —— 会告诉你哪个岗位缺了必填项
npm run config:check

# 4. 启动
npm run dev
```

`config/*.json` 已在 `.gitignore` 中排除——你自己的业务数据不会被误提交。

### 启用平台

默认只开 BOSS。要用猎聘，改 `config/workflow.json`：

```json
"platforms": {
  "enabled": ["boss", "liepin"],
  "liepin": { "enabled": true, "profileDir": "", "cdpPort": 9333 }
}
```

`profileDir` 留空则用本机默认路径——**这个 profile 是给 RPA 专用的**，不要和你日常
用的 Chrome 共用，两边的登录态互相干扰会让风控基线失真。

首次运行前，在该 profile 里手动登录一次 BOSS / 猎聘。RPA 不保存任何账号密码，
它只是驱动你已登录的会话。

### 导入岗位

```bash
npm run seed:jds                       # 全部写入，都不激活
npm run seed:jds -- --active=jd_xxx    # 顺便激活指定岗位
```

### 打包

```bash
npm run build            # 安装包 + 便携版 → release/
npm run build:dir        # 仅未打包目录
npm run build:portable   # 仅便携版
```

### 测试

```bash
npm test                 # 全量测试（mock 掉 CDP，不需要真浏览器）
npm run typecheck
npm run score:check      # 评分引擎分布体检
npm run score:eval       # 用你自己的锚点集做三档验收
```

## 接入你自己的业务数据

这个仓库**不带任何真实岗位、简历、组织架构或租户信息**。克隆下来是一个空壳工具，
你需要把自己的东西填进去。全程只改 `config/` 目录，不用碰代码。

一个岗位长这样：

```json
{
  "id": "jd_your_position",
  "name": "你的岗位名",
  "title": "招聘平台上这个职位的名字",
  "basic": { "degree": "本科", "experienceMin": 3, "experienceMax": 8, "city": "上海" },
  "keywords": {
    "required": ["必须会的词"],
    "bonus": ["加分词"],
    "negative": ["一出现就减分的词"]
  },
  "domain":  { "label": "应用领域", "keywords": ["领域词1", "领域词2"] },
  "tasks":   [{ "name": "具体做过的事", "keywords": ["证据词"], "domainSensitive": true }],
  "hardFlags": { "experience": false, "degree": true }
}
```

四个字段的取舍，直接决定你的评分准不准：

| 字段 | 不填的后果 | 建议 |
|---|---|---|
| `domain`（应用域） | 占 20% 权重整维退出，`金融风控` 和 `电商推荐` 打成同一档 | **一定要填** |
| `tasks`（任务点） | 占 20% 权重整维退出，退化成只看技术词面 | **一定要填** |
| `keywords.required` | 硬技能维靠加分词排序，但不制造拒绝 | 只放**真正不可谈**的词 |
| `hardFlags.experience` | 设为 `true` 会用年限硬卡人 | 默认 `false`——年限弹性是常态 |

完整字段说明、飞书租户配置、Excel 台账映射、自建标定语料：
→ **[接入你的业务数据](docs/接入你的业务数据.md)**

## 浏览器扩展

RPA 跑完之后，剩下的往往是**你自己打开 BOSS 网页手工看人**。扩展是这条路径上的补丁：
不用切回 App，卡片上直接看到分数。

`extension/` 下是三个**互相独立**的扩展，各自打包、各自安装，不共享代码也不共享存储：

| 扩展 | 用途 | 风险面 |
|---|---|---|
| `boss-match-score` | 人工 sourcing 时在推荐卡片上贴匹配分徽章 | 只读已渲染 DOM，**零平台请求** |
| `feishu-req-sheet-sync` | 读飞书招聘需求，汇总进本地 Excel | 只访问飞书 |
| `feishu-req2job` | 飞书需求 → 新建职位，自动填到提交前停下 | 只操作飞书页面，**绝不替你提交** |

为什么用扩展而不是往页面注入脚本：平台注入需要浏览器带 `--remote-debugging-port` 启动并被附着，
而这恰好落在招聘平台的自动化检测射程里。**为了显示一个徽章去开调试端口，是用最高风险的方式
实现最低风险的需求。** 扩展是 Chrome 原生能力，不需要调试端口，content script 天然运行在隔离世界。

三条硬约束（改代码时勿破）：零平台请求、避开 DOM 蜜罐、只读不写。细节见 [`extension/README.md`](extension/README.md)。

## 工具系统

一个工具就是一个目录：一个 `*.tool.json` manifest + 一个或多个 content script。

```
tools/
└── my-tool/
    ├── my-tool.tool.json
    └── content.js
```

```json
{
  "id": "my-tool",
  "name": "我的工具",
  "version": "1.0.0",
  "matches": ["*://example.com/*"],
  "entry": "content.js",
  "configSchema": [
    { "key": "key", "label": "配置项", "type": "string", "default": "value" }
  ]
}
```

放到 `tools/` 下 → 工具库页刷新 → 打开开关。脚本通过 `window.__TOOL_CONFIG__['<id>']` 读配置。

## 使用前必读

这几条是真实跑出来的坑，不是理论。

**1. 运行 RPA 时浏览器窗口必须可见。** 最小化或被完全遮挡时 Chrome 不处理 CDP 输入事件，
`Input.dispatchMouseEvent` 永不回执，翻不动推荐流。引擎会在开跑前检测并拒绝启动——
"跑出一个假的任务完成"比不跑更糟。单次运行最长 90 分钟，请预留屏幕。

**2. JD 必须和目标平台上的那个职位对得上。** BOSS 的推荐流是按你在平台上的职位推的人，
猎聘的搜索结果也受你选中的职位影响，而分数是按平台里这份 JD 算的。两者不是同一个岗位时，
会表现为"分数集体偏低"——这不是评分故障，是在如实告诉你"推来的人不匹配你描述的岗位"。

**3. 应用域和任务点值得花十分钟填。** 不填不报错，但这两维会整维退出加权，
评分退化成只看技术词面。代价可量化：在自己的锚点集上，不填时引擎会把人工 80 分的人
排在 60 分的人**后面**（倒挂 -8）；填了之后分档命中 100%。

**4. 每个分数都带数据覆盖度。** 覆盖度低于 60% 不会被判为"高匹配"，也不会触发自动打招呼——
打招呼不可撤回，证据不足就不发。

**5. 夜间禁跑（22:00–07:00）。** 这是硬约束，不可配置。

**6. 改过评分逻辑后必须重建插件产物。** `src/shared/scoring-universal.js` 是 App 与插件共用的
引擎，插件跑的是 `content.bundle.js` 这个构建产物。`npm run build` 会自动带上 `ext:build`，
但直接 `npx vite build` **不会**，产物会悄悄落后。改完跑 `npm run ext:build`，
`npm run ext:check` 可校验是否同步。

## 核心原则

1. **单人单机** —— 每个人用自己的账号、自己的电脑、自己的行为模式
2. **人等价速度** —— 追求"跑得像人"，不追求"跑得快"
3. **授权账号** —— 只用使用者本人已登录的浏览器会话
4. **全程可控** —— 可随时暂停/停止，风险升高自动提醒
5. **最小必要** —— 只提取评分要用的字段，长文本只在内存参与算分、不落库

## 边界与免责

本项目**不破解、不绕过**任何平台的风控。它做的是行为节奏拟人化 + 风险监控预警 +
命中风控后自动退避。使用自动化工具访问招聘平台仍可能违反其服务条款，
**后果由使用者自行承担**。请只在获得授权的账号与场景下使用。

本仓库不含任何真实候选人数据、岗位定义或组织架构。`config/*.json`、`corpus/`、
`data/`、猎聘 RPA 的输出目录等均已在 `.gitignore` 中硬性排除——
这是红线，不要为了调试把它们提交上去。

## 参与共建

这个项目是从真实的招聘工作里长出来的，目前只覆盖 BOSS 和猎聘两个平台。
**最想要的贡献是"多一个平台"**——每接一个招聘平台，这个工具对更多人才真正可用。

- **接新招聘平台** —— 在 `src/main/services/adapters/` 下实现 `PlatformAdapter` 并注册。
  优先想要：脉脉、拉勾、前程无忧、智联招聘、LinkedIn、内推系统
- **补平台细节** —— 已有平台的选择器失效、风控信号漏检，都是高价值修复（带真机截图最好）
- **改进评分** —— 带上你自己的标定语料，能复现的实验结论最受欢迎
- **报 bug / 提需求** —— 开 issue 说清"你想做什么、卡在哪"，比只写"用不了"有用得多
- **完善文档** —— 你踩过的坑，就是下一个人最需要的那篇文档

PR 请保持一个主题一件事。改 RPA 或选择器的，请说明测试的平台版本与页面结构；
改评分逻辑的，请附上改动前后的对比数据。
