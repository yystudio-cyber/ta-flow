# 飞书需求 → 桌面 Excel 自动汇总 · 使用说明

## 这是什么

TA Flow的「飞书需求汇总」工具：在 Chrome 里装上扩展后，自动读取飞书招聘需求列表，把**审批通过**的新需求逐条提取字段，写入桌面的《招聘进展表》Excel。

只读不写飞书，只追加不删 Excel 现有行，不提交任何内容。

---

## 一、安装扩展

1. 打开 TA Flow，进入「工具库」页面
2. 在「飞书需求 → 表格自动汇总」卡片上，点「一键安装」
   - 平台会自动打开 `chrome://extensions` 页面
   - 同时把扩展目录路径复制到剪贴板
3. 在 `chrome://extensions` 页面右上角，打开「**开发者模式**」
4. 点「**加载已解压的扩展程序**」，在地址栏 `Ctrl+V` 粘贴路径，点「选择文件夹」
5. 装好后扩展列表里会出现「**飞书需求 → 表格自动汇总**」

> **注意**：必须装在 Chrome 里（你日常用的那个），不能用 Edge 等其他浏览器。平台只跟 Chrome 通信。

---

## 二、选择 Excel 目标文件

1. 在平台「设置」页面找到「需求汇总」区域
2. 点击「选择 Excel 文件」，选你桌面上的 `招聘进展表.xlsx`
3. 首次使用如果没有这个文件，平台会自动从内置模板创建一份到桌面

**表头说明**：必须保持 15 列表头不变（含中英双语），工具会校验表头——格式不对会拒绝写入并提示差异。

---

## 三、首次运行

1. 确认扩展已装好（Chrome 扩展列表里能看到）
2. 在平台「工具库 → 飞书需求汇总」卡片，点「**打开并汇总**」
3. 平台会拉起你的 Chrome，打开飞书招聘需求列表页
4. 如果你还没登录飞书，页面上方会出现 `⏳ 等待登录中…` 的横幅——正常登录即可，登录后扩展会自动继续
5. 扩展自动扫描需求列表 → 过滤审批通过 → 逐条打开详情提取字段 → 写入 Excel
6. 完成后横幅显示 `✅ 完成：写入 N 条`

> **首次运行会处理所有历史审批通过的需求**。之后的运行只处理新增的。

---

## 四、每天 11:00 自动运行

- 默认**每天上午 11:00** 自动触发一次
- 启动时如果今天的定时还没跑，会自动补跑（`catchUpOnStart`）
- 单次最多处理 **50 条**新需求，超过的延到下次运行
- 可在「设置 → 需求汇总」里关闭定时或修改触发时间

**自动运行的机制**：平台每 60 秒检查一次本地时间，到达设定时间且今天还没跑过就触发。不会因为合盖/休眠而漏跑——醒来后会补。

---

## 五、表格被 Excel 占用时怎么办

如果运行时 `招聘进展表.xlsx` 正被 Excel 打开（锁住了）：

1. 数据不会丢失——自动落入 **pending queue**（SQLite 暂存）
2. 右下角横幅会提示 `⚠ 文件被占用，数据已暂存`
3. **下次运行时会自动把 pending queue 里的数据一起写入**（优先 flush）
4. 或者你关掉 Excel 后，在平台点「打开并汇总」手动触发一次

流程：`检测到文件锁 → 写入 pending queue → 下次运行 drain pending → 一起入 Excel`

## 六、企业网关拦截页

如果你用的是公司配的安全浏览器（如阿里办公安全），打开飞书时会先经过网关拦截页：

- 页面显示「安全访问」或「跳转安全浏览器立即访问」
- 扩展检测到网关拦截页后，横幅会提示 `🔒 企业网关拦截`
- **解决办法**：点击页面上的「跳转安全浏览器立即访问」按钮，进入飞书后一切照常

## 七、调试开关

如果扩展不工作、想排查问题：

1. 在飞书招聘需求列表页按 `F12` 打开控制台
2. 在控制台输入以下命令（注意是 **setItem**，不是 getItem）：
   ```js
   localStorage.setItem('ta-rss:debug', '1')
   ```
3. 刷新页面（`F5`）
4. 控制台会输出 `[feishu-req-sheet-sync]` 开头的调试日志
5. 用完记得关闭：
   ```js
   localStorage.removeItem('ta-rss:debug')
   ```
   然后刷新页面

> **常见误区**：`localStorage.getItem('ta-rss:debug')` 是读取，设成 `'1'` 不生效。必须用 `setItem`。

## 八、常见问题

### Q: 点「打开并汇总」后没反应？
- 确认 Chrome 扩展已装好（`chrome://extensions` 里能看到）
- 确认扩展的 `key` 与平台配置的 `REQSHEET_EXTENSION_ID` 一致
- 打开控制台看有没有报错

### Q: 飞书页面打开了但横幅不出现？
- 扩展的 `content_scripts.matches` 需要覆盖当前页面 URL（`https://*.feishu.cn/hire/*`）
- 确认扩展已启用（开关是开的）

### Q: Excel 里重复写入了同一条需求？
- 不会。工具写前会读出 O 列（需求编号）去重，已存在的自动跳过。

### Q: 备份在哪里？
- 每次写入前自动备份到 Excel 同目录，文件名格式：`招聘进展表.bak-YYYYMMDD-HHmmss.xlsx`
- 只保留最新 10 份，旧的自动清理

## 附：0级/1级部门为什么是空的（需要 HR 补一次对照表）

真机确认（2026-08-10，测试租户）：飞书需求详情页的「需求部门」**只显示叶子部门名**
（如「ACME中国1」「质量控制组」），页面 DOM 里没有任何上级路径信息，
因此 0级/1级部门**推导不出来**。工具的选择是**留空**，而不是猜一个填进去。

补齐办法：在 `tools/_shared/req-to-sheet-map.js` 的 `DEPT_LEVEL_LOOKUP` 里登记对照关系：

    var DEPT_LEVEL_LOOKUP = {
      'ACME中国1': { level0: 'ACME', level1: 'ACME中国1' },
      '质量控制组':  { level0: 'XXX',    level1: 'YYY' },
    };

登记过的部门会自动填 A/B 两列；没登记的仍然留空，并计入运行报告的"未映射"计数——
这样一眼能看出还有哪些部门没登记，而不是悄悄写错。组织架构来源见 `总结\示例 HR组织架构.docx`。

## 附：哪些列天然会是空的

| 列 | 情况 |
|---|---|
| 关键岗位 / 紧急度 | 飞书需求里**没有这两个字段**，只能人工填 |
| 0级/1级部门 | 见上，需登记对照表 |
| 审批具体时间 | 部分老需求页面上**没有「审批信息」区**（实测 R00012、R00003 等），此时留空 |
| Lead Time cutoff 180D | 由审批时间 +180 天算出；审批时间为空时它也为空 |
| 其余列 | 飞书里填了就有，没填就是空——工具不会拿 `--` 占位符冒充有值 |
