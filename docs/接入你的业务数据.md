# 接入你自己的业务数据

这个仓库**不含任何真实岗位、简历、组织架构或租户信息**。克隆下来是一个空壳工具，
你需要把自己的东西填进去。全程只改 `config/` 目录，不用碰代码。

## 三步接好

```
1. 复制模板        2. 填自己的数据       3. 自检并启动
config/*.example.json → config/*.json    npm run config:check → npm run dev
```

### 第 1 步：复制配置模板

```bash
cp config/jd-config.example.json  config/jd-config.json    # 岗位库
cp config/workflow.example.json   config/workflow.json     # 平台/飞书/台账
```

`config/*.json` 已在 `.gitignore` 里排除，**你的业务数据不会被误提交**。

### 第 2 步：填岗位库

打开 `config/jd-config.json`，把示例岗位换成你自己的。一个岗位长这样：

```json
{
  "id": "jd_your_position",
  "name": "你的岗位名",
  "title": "招聘平台上这个职位的名字",
  "basic": { "degree": "本科", "experienceMin": 3, "experienceMax": 8, "city": "上海" },
  "keywords": {
    "required": ["必须会的词"],
    "bonus": ["加分词", "另一个加分词"],
    "negative": ["一出现就减分的词"]
  },
  "domain":  { "label": "应用领域", "keywords": ["领域词1", "领域词2"] },
  "tasks":   [{ "name": "具体做过的事", "keywords": ["证据词"], "domainSensitive": true }],
  "hardFlags": { "experience": false, "degree": true }
}
```

四个字段的取舍，直接决定你的评分准不准：

| 字段 | 不填的后果 | 建议 |
|---|---|---|
| `domain`（应用域） | 占 20% 权重整维退出，`金融风控` 和 `电商推荐` 打成同一档 | **一定要填** |
| `tasks`（任务点） | 占 20% 权重整维退出，退化成只看技术词面 | **一定要填** |
| `keywords.required` | 硬技能维靠加分词排序，但不制造拒绝 | 只放**真正不可谈**的词 |
| `hardFlags.experience` | 设为 `true` 会用年限硬卡人 | 默认 `false`——年限弹性是常态 |

> 关于 `domain` 为什么最关键：同一堆技术词，「金融风控引擎」和「电商推荐引擎」是两拨人。
> 没有域信息，引擎分不出来。实测不填时，人工 80 分的人会被排在 60 分的人后面。

### 第 3 步：填工作流

`config/workflow.json` 管这些：

- `platforms` —— 开哪些招聘平台、各用哪个浏览器 profile / 调试端口
- `feishu.tenantSubdomain` —— 你的飞书招聘租户子域（`mycorp` → `mycorp.feishu.cn`）
- `excel.ledgerPath` + `columnMap` —— 飞书需求汇总写到哪个 Excel，列名怎么对应
- `corpus.resumeDir` —— 放你自己匿名化简历的目录，`npm run score:eval` 会读它

### 第 4 步：自检

```bash
npm run config:check
```

它会告诉你：哪个岗位缺了 `domain`、飞书租户还是占位值、台账路径没配。
`✗` 必须修完才能跑；`!` 是吃亏但能跑的提醒。

## 导入岗位到平台

```bash
npm run seed:jds                       # 全部写入，都不激活
npm run seed:jds -- --active=jd_xxx    # 顺便激活指定岗位
```

写入后到「岗位库」页面刷新就能看到。

## 校准备用：自己攒一套标定语料

想让分数"有据可依"而不是拍脑袋，可以拿双标签简历做回测：

```bash
node tools/build-corpus.mjs --data=<你的简历目录> --out=./corpus/ta-corpus.json
npm run score:eval          # 三档验收：正样本误杀率 / 负样本识别率 / 排序方向
```

**简历必须是匿名化后的**。`corpus/` 已在 `.gitignore` 中排除，永远不要提交。

## 换成别的招聘平台

`src/main/services/adapters/` 下每个平台一个适配器。加新平台：

1. 在 `config/workflow.json` 的 `platforms` 里加一个键
2. 照 `boss.ts` / `liepin.ts` 的结构实现 `search / listCards / openDetail / greet`
3. 在 `adapter-lab.mjs` 里加一组合成页面的断言

适配器不用改评分引擎——引擎是平台无关的纯函数。

## 常见坑

**用了示例配置还抱怨分数不准。** 示例岗位是给人看格式的，不是拿来评分的。
先 `npm run config:check` 确认它没在提示「正在使用示例」。

**飞书工具装上了但页面没反应。** 改完租户子域要重装或刷新扩展；
已经开着的飞书页面按 F5。

**Excel 汇总没写进去。** 检查 `excel.ledgerPath` 是绝对路径、目标文件没被 Excel 独占打开、
`columnMap` 的左侧列名和真实表头逐字一致（含空格）。
